# AXOM

AXOM is a private academic operating system for high-pressure learners — a
local-first question bank, study engine, and command center. The pre-beta is
centered on the deployable Vite/React web app in [`web/`](web/) with optional
Vercel serverless backend sync.

> Note: the repository folder, native compatibility type names, and persisted
> storage keys intentionally retain some `noctyrium-*` identifiers so existing
> installs keep their data. Release-facing package names and UI use AXOM.

The app combines:

- A review-gated Question Bank for PDF, DOCX, text, CSV, JSON, and pasted sets
- Tutor/exam blocks with clean feedback, source evidence, repair actions, and progress
- Course, term, module, Lecture, DLA, and PQ tracking
- Pass/mastery tracking with Anki-aware study status
- Productivity logging, daily standups, journal, reports, and tasks
- Step 1 / Step 2 prep surfaces
- Resources, prompt library, hub folders, and JSON backup/import
- Optional name-only cloud progress save, cloud backups, restore, and AI provider scaffolding

## Current Pre-Beta Status

- **Version:** `0.0.1-prebeta`
- **Data schema:** `v32`
- **Frontend:** Vite + React + TypeScript in `web/`
- **Backend:** Hobby-safe grouped Vercel serverless functions in `api/`, with shared backend code in `lib/api/`
- **Database:** Neon/Supabase/Postgres via `DATABASE_URL`
- **Persistence:** Local Vault first; cloud sync is optional
- **Desktop shell:** experimental Tauri v2 + SQLite scaffold in `src-tauri/`
- **Package:** static web zip and double-clickable macOS wrapper are generated by `npm --prefix web run package`

The current pre-beta opens with a fresh SGU-oriented scaffold. It keeps Terms 1-5 and the
main BPM/SPPM/PPM course shells, but only includes a few example Lecture/DLA/PQ
rows so new users are not inheriting a personal workload.

## Question Bank Workflow

The flagship loop is:

`Import → map → review uncertainty → save → build a block → answer → clean feedback → repair → retain progress`

- The Command Center surfaces the next useful action, six core metrics, due/missed/
  weak-topic blocks, recent libraries, and grounded insights.
- Digital-text PDFs are extracted per page; DOCX preserves paragraph structure; TXT,
  Markdown, CSV, JSON, pasted text, and multi-file queues share the review pipeline.
- The layered parser separates stems, multiline options, answer keys, feedback,
  explanations, objectives, and provenance. It maps letter or answer-text signals,
  flags conflicts instead of guessing, and stores per-stage confidence, rule IDs,
  warnings, source snippets, and answer evidence.
- Deterministic explanation cleaning removes duplicated stems/options/answer lines.
  Quiz feedback then shows the result, correct answer, learner answer, real rationale,
  optional objective, and collapsible source evidence as separate regions.
- Question-set cards show completion, remaining work, accuracy, last study time,
  import confidence, review count, and the specified green/gold/orange/red thresholds.
- Source checksums prevent duplicate document records; schema v32 migrates existing
  questions additively and retains JSON backup/merge compatibility.

During local development, `#design-preview` provides a reusable real-component AXOM
preview with quiet/balanced/contrast variants and loading, empty, error, review,
correct, and incorrect states. It is not a production route or navigation item.

## Current Limitations

- Scanned/image-only PDFs and screenshots do not have OCR. They can be recorded as
  provenance, but AXOM does not pretend that image text was extracted.
- Modern `.docx` is supported; legacy binary `.doc` is not.
- Source records retain extracted text, page text, metadata, and a checksum — not the
  original PDF/DOCX binary. Keep the original file outside AXOM.
- AI is optional. The deterministic parser, review, quiz, and storage loop works without
  it; AI actions require a reachable configured provider/model. Cloud BYOK remains
  disabled until a secure server-side endpoint exists, and demo output is labeled.
- The Local Vault is browser-origin/device-local. Browser cleanup can remove it, and
  changing domains, browsers, devices, or package types does not automatically carry
  it over. Export a JSON backup before doing so.
- Parser confidence is evidence for review prioritization, not a guarantee of medical
  correctness. Conflicts and low-confidence mappings still require a human decision.

## Run Locally

Frontend only:

```sh
cd web
npm install
npm run dev
```

Full Vercel-style app with API routes:

```sh
npm install
cp .env.example .env.local
npm run dev
```

Without `DATABASE_URL`, the app still works locally through the browser Local
Vault and JSON backups. Cloud progress save requires a Postgres connection.

## Backend Setup

Recommended production setup:

1. Create a Neon or Supabase Postgres database.
2. Set `DATABASE_URL` in Vercel.
3. Use `AI_PROVIDER=mock` only for explicitly labeled demo behavior; the core app does not require AI.
4. Run the SQL in [`db/migrations/001_initial.sql`](db/migrations/001_initial.sql), or leave `NOCTYRIUM_AUTO_MIGRATE=true` so the serverless API creates the schema on first use.

Core public API URLs:

- `POST /api/user/login`
- `GET /api/user/:id`
- `GET /api/data/:userId`
- `POST /api/data/:userId`
- `POST /api/data/:userId/backup`
- `GET /api/data/:userId/backups`
- `POST /api/data/:userId/restore/:backupId`
- The frontend “save/load by name” flow composes `POST /api/user/login` with the data endpoints so the deployment stays under the Hobby plan serverless function limit.
- `POST /api/ai/next-move`
- `POST /api/ai/anki-generator`
- `POST /api/ai/step-planner`
- `POST /api/ai/weak-area-analysis`
- `POST /api/ai/daily-report`

Those URLs are compatibility rewrites. Vercel only deploys five route files:
`api/user.ts`, `api/data.ts`, `api/ai.ts`, `api/feedback.ts`, and
`api/health.ts`, keeping the pre-beta below the Hobby plan serverless function cap.

Name login is lightweight identity, not secure authentication. For production
multi-user use, migrate to email magic links, OAuth, or passkeys.

## Deploy To Vercel

Use the repository root as the Vercel project root. The root `vercel.json`
builds `web/`, serves `web/dist`, and keeps `/api/*` on serverless functions.
The API is grouped into five functions, so the Hobby deployment should pass the
function-count check.

```sh
npm install
npm run typecheck:api
npm run build
find api -maxdepth 1 -type f -name '*.ts' | wc -l  # should print 5
```

If Vercel shows `404: NOT_FOUND`, the project is usually pointed at the wrong
root or an older deployment. Redeploy from the repository root after committing
the Vercel config.

## Package

```sh
npm --prefix web run package
```

This creates versioned static-web and, on macOS with `swiftc`, double-clickable
wrapper archives under `web/`. The terminal output prints the exact filenames.

Generated packages, `dist/`, cache files, and personal study folders are ignored
and should not be committed.

## Experimental Tauri Desktop Shell

The pre-beta still distributes the static web zip and lightweight macOS wrapper, but
the repository now includes a real Tauri v2 scaffold for the future native app:

```sh
npm run tauri:dev
npm run tauri:build
```

The Tauri shell preloads `sqlite:noctyrium.db` through the SQL plugin and starts
with a `local_vault_snapshots` table. This is experimental; Local Vault remains
the active source of truth in the current pre-beta.

## Desktop packages and updates

- **Hosted web app:** new deployments are detected by build identity. Users
  choose when to refresh; offline caching retains the current app until then.
- **Tauri desktop app:** signed updater checks, downloads, verifies, then saves
  a recovery snapshot before a user-approved install/restart. Public updates
  require signing credentials and a reachable HTTPS feed. Local unsigned
  packages explicitly disable updates.
- **Packages:** `npm run release` builds native packages plus a web ZIP;
  `npm run release:web` builds only the web ZIP. `npm run release:doctor`
  checks prerequisites. Outputs live in `dist/releases/<version>/`.
- The Local Vault is per-browser/origin, so **always Export a JSON backup**
  (Settings → Backup) before switching devices, domains, or package types.
