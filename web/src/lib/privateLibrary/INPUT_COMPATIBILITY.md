# Local collection intake

This compatibility adapter feeds the existing `installPrivateLibrary` path. It does not create a question engine, a cloud catalog, or an approval bypass.

Accepted: root/wrapped prepared catalogs, native manifest/questions/assets folders, and a single flat `questions.json` export with its `assets/` folder. Native packages and flat exports produce a virtual catalog only in memory. Source words, question IDs, set/number relationships, week scope, answer evidence, flags, and asset visibility are preserved by the canonical readers. The original is hashed when supplied; absent original bytes are reported, never invented.

Flat exports require unique question IDs and consistent bank/course/term metadata. They preserve every row and the exact original JSON. A bare answer letter has no verified evidence and stays in review; unknown source review flags also hold the question. Null weeks remain unassigned. Matching items remain unresolved rather than being silently converted to single-answer questions. Single-answer questions may contain two through nine choices. Shared image aliases receive separate question ownership without changing image bytes or removing questions. Rich stem blocks take precedence over their plain-text aliases, avoiding a repeated preview. The export checksum identifies JSON, never an absent PDF.

Native packages accept a conventional trailing slash on `assetsDirectory` and honor their declared nested `questionsFile`. A separate undeclared question export beside a native package is rejected rather than omitted. Packaging metadata such as `__MACOSX` is ignored consistently.

ZIP preflight rejects duplicate/case/Unicode path collisions, unsafe paths, symlinks, unsupported layouts, per-file/total bounds, and mismatched local headers. Streaming reads validate actual inflated lengths and CRC before delivering bytes. ZIP64, encrypted, legacy non-UTF-8 and split archives use the folder route instead. This is bounded archive intake, not a malware scanner.

Original PDFs up to 256 MiB can be retained and viewed one page at a time; other files remain limited to 128 MiB and the expanded collection to 2 GiB. Raw PDF text extraction keeps its separate size/page bounds. Retaining a large scanned original does not establish that its questions have been extracted or checked.

Package preflight holds questions exceeding the durable allowance of ten images or 30 MiB per question before any partial save. Additional teaching pages can stay in source-reference PDFs. Reinstalling a held bank preserves its candidate key and flags; an explicitly cleared key remains absent.

A missing named image is a clear error; no image is guessed or silently reattached. Each prepared question must bind to its catalog source with the canonical `sha256:` checksum before its first installation, so an invalid binding cannot fail only on reimport. Raw PDFs/Word/text without a native manifest still use the existing QBank file importer. Source answer evidence is not human approval. No local input is sent to the cloud by this module.

Tests: `inputRoot.test.ts`, `zipIndex.test.ts`, `nativeInput.test.ts`, `questionExport.test.ts`, `fileInput.test.ts`, and `install.test.ts`; browser coverage is in `flat-question-export.spec.ts`. `AXOM_PRIVATE_BUNDLE` enables the opt-in local acceptance test for a private ZIP, with optional `AXOM_ACCEPTANCE_REPORT` and exclusive-create `AXOM_PREPARED_OUTPUT` paths outside the repository. It verifies direct installation, persistence/reload, and repeat installation without duplicates. Browser tests separately verify actual image decoding, reveal visibility, scoring, and responsive preview. Before merge, run web typecheck/lint/build and affected tests. Hosted release and multi-user publication are separate acceptance gates tracked in issue #22.
